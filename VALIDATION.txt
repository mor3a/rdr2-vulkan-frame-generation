RDR2 Vulkan FG 0.22 - validation and performance notes

Hardware: NVIDIA GeForce RTX 3050 Laptop GPU, 4096 MB VRAM.
RDR2 1.0.1491.50, NVIDIA driver 616.56, Vulkan, 1920x1080 SDR.
DLSS input size: 1280x720. Measurements are scene-specific, not guarantees.

Fixed-scene comparison on the 0.21 optimization candidate, same camera:
Each stage: 6 seconds warmup followed by 12 seconds sampling.
Stage            Rendered FPS   Displayed FPS   p95 real interval (ms)
FG off A             62.75          62.75              19.709
2x extra wait A      41.78          83.56              24.641
2x no extra wait     43.50          87.00              23.565
3x extra wait        36.42         109.25              28.354
3x no extra wait     37.75         113.00              26.959

Removing the optional extra GPU wait improved displayed throughput by about
4-5% and the p95 real-present interval by about 4-5% in these samples.
GPU utilization remained 97-98%; VRAM use was approximately 3.1-3.3 GB.
FG GPU work still reduces rendered FPS. These are backend-reported displayed
counts and game-present intervals, not independent monitor scanout/latency
measurements. The 0.22 release retains the measured no-extra-wait path and adds
off-path/UI buffer synchronization corrections. It was not re-benchmarked
under identical environmental conditions after those small changes.

Automated validation: 8 input/resource contract checks, 3 NGX ABI forwarding
checks, 5 FPS sampling checks, all passed on the release build. FPS checks
cover off, 2x, 3x, telemetry loss and recovery after a pause.

Runtime checks: DLSS-G candidate sustained 3.00x, status 0 in the long run.
FSR3 release candidate reported 598 displayed increments over 299 real-frame
intervals (2.00x). Menu Off returned it to 299/299 (1.00x); closing the menu
with Off retained 1.00x. Re-enabling resumed 597/299 (2.00x), without runtime
prepare/interpolation/configuration errors. The optional FPS checkbox hid the
counter. Vulkan menu dragging was exercised against the game image.

A later UI fix binds ImGui upload buffers to the acquired game-image index
and its completion fence, rather than rotating independently. Upstream ImGui
copyrights remain intact. Final runtime checks are recorded below.

Known limits: slight FSR HUD ghosting can remain. FSR3 3x is not implemented.
DLSS-G 4x, physical RTX 20, HDR, live resize and other games are unvalidated.
A finite test cannot establish that every configuration is crash-free.

Final FSR3 build (ASI SHA256 070A3DA446B8AF842E95E98A8820EB7C06B0BC50D9F2FF23CFA1097D6E99FC50): native 2.00x verified, menu paused to 1.00x and resumed to 2.00x. Title-bar drag and provider selection worked. Text remained intact in the post-fix menu observations. Provider selection wrote DLSSG with a restart notice. No secondary menu window or backend errors observed.

Final DLSS-G build: 300 presents / 900 displayed frames (3.00x), status 0. Opening the menu suspended FG to 1.00x. Selecting 2x and closing it resumed to 300 / 600 (2.00x), status 0. The counter displayed rendered/output text with no background. A transient text artifact was observed in one dropdown interaction; a permanent clean-menu guarantee is not established. The synthetic Escape input did not activate the game's pause screen, so that particular pause-screen transition was not validated. Story loading and in-game menu suspension/resumption were exercised. No crash or device-loss error occurred in these final runtime checks.
